# Utattemita Implementation Learnings — Draft Snapshot

> Status: Draft / Non-normative  
> 本文書は、utattemita.united-studio.com の実装結果から得られた判断を、UDSL Core + Extensions再整理のために保存する作業中メモである。正式なUDSL仕様ではない。

## 1. Context

`rec.united-studio.com` は、機能、料金、対応範囲、信頼を説明するサイトとして成立している。

一方で、20代女性を中心とする「歌ってみた」初見ユーザーにとっては、少し重く、かっちりしすぎる可能性がある。情報が正しくても、「自分も歌ってみたい」という気持ちが予約行動へ移る前に弱まることがある。

Google広告のコンバージョン計測がよりシビアになる状況では、初見ユーザーがその場で自分との関係を理解し、次の行動へ進む割合が重要になる。

`utattemita.united-studio.com` は `rec` の置き換えではない。機能と信頼を説明する `rec` とは異なる心理導線を持つ入口である。

目的は、**「歌ってみたい気持ちを、予約できる気持ちに変える」こと**である。

## 2. What Changed from the First Draft

最初のv0案は、次の方向へ寄りすぎていた。

- 安心感
- アイボリー
- ピアノ教室感
- 習い事感
- 初心者向け講座感
- 説明型LP感

この方向は不安を減らす一方で、「歌ってみた」や投稿文化へ入るときの期待、勢い、自分も参加できそうだという感覚を弱めていた。

実装では、入口の役割を次の方向へ切り替えた。

- POP
- FUN
- 攻めている
- うたみたカルチャー
- 投稿文化
- 写真主役ではなく、タイポグラフィとグラフィック主役
- 安心感は後半で戻す

安心感を削除したのではない。最初に出す感情と、後から確認する信頼の順序を変えた。

## 3. Final Direction

完成版のHEROは、次のコピーを主役にした。

```text
歌うだけで、
一曲になる。
```

HEROでは写真で安心させない。シアンの背景、太い黒文字、ピンクのCTA、ステッカー感、グリッド、ポスターのような構成によって、最初にPOP / FUN / 攻めを伝える。

操作UIはUtattemita人格で統一する。一方で、favicon、metadata、footer、copyrightはUnited Studio人格を担い、サービスの帰属と信頼を維持する。

情報は一つのサイトへ抱え込まず、役割ごとに引き渡す。

| Destination | Role |
| --- | --- |
| `rec` | 細かい説明、料金、対応範囲、詳しいFAQ |
| `studio` | 設備、空間、制作環境 |
| `reserve` | 空き状況確認と予約実行 |

Utattemitaは、すべてを説明する場所ではなく、次の行動を選べる状態をつくる入口として完成した。

## 4. Copy Learnings

採用した中心コピーは、サービスの仕組みではなく、利用者に起こる変化を一息で伝える。

```text
歌うだけで、
一曲になる。
```

採用した方向性：

- 好きな曲を、自分の声で。
- 録音もミックスも一緒に進むから、あなたはマイクの前で歌うだけ。
- その声、録ってみよう。
- 空き状況・料金を見る
- 見るだけでも大丈夫です

避けた方向：

- 初心者でも簡単
- プロ品質保証
- 上手くなってから
- まずはボイトレ
- 教室的な安心感
- 説明しすぎるLP

「初心者」と呼び続けるより、今の声で始められることを示す。大きな見出しは気持ちを動かし、その直後の短い本文は録音、ミックス、料金、次の行動を具体化する。

## 5. Sample Strategy

サンプルは大量掲載しない。上手い作品例を並べ、利用者へ比較や評価を促す場所にしない。

Utattemitaでは、サンプルを実際の2時間セッション例として扱う。作品の完成度を証明するより、当日のテンポと、自分の声が作品になるまでを理解できることを優先する。

古い映像でも、現在のサービス内容と大きく矛盾せず、体験理解に役立つなら使用できる。高完成度の作品例が必要な場合は、`rec`、`studio`、将来の `works` へ役割を渡す。

完成版のSESSION SAMPLEは、次の時間構造を採用した。

```text
14:00
01
IN
スタジオ入り。曲と声を一緒にチェック。

14:10
02
FIRST REC
まずは1曲通します。声出しをしながら、エンジニアが曲構成を把握します。

14:15
03
REC & SELECT
歌う。何テイクか重ねて、いい瞬間を残す。
好きなテイク選びも、一緒に。

15:10
04
MIX
声を整えて、伴奏の中へ馴染ませる。

15:30
05
VIDEO?
撮りたければ、投稿用の動画も。

15:55
06
DONE
完成版をファイルで受け取り。
```

サンプルの役割は「このレベルでなければ利用できない」と感じさせることではない。「自分の一曲も、この順序で始められる」と理解させることである。

## 6. Trust Handoff

安心感はHEROの主題にせず、判断に必要になるタイミングで戻す。

HEROでは、世界観を崩さない短い事実として「歌うだけでOK」「録音＋MIX」「当日完成」を置く。その後のSession、料金、FAQで次の情報を具体化する。

- 2時間から
- エンジニア付き
- 録音・ミックス・マスタリング
- 当日完成
- 空きを見てから決められる
- LINE相談
- `rec` FAQ
- `studio` 詳細
- `reserve` 予約システム

`空き状況・料金を見る` の近くに、予約システムへ移動することと、見るだけでもよいことを示す。信頼は一つの強い説明ではなく、事実、選択肢、外部ハンドオフの積み重ねでつくる。

## 7. Brand Identity Split

今回の重要な判断は、操作時に感じる人格と、サービスの帰属を示す人格を分離したことである。

```text
操作UI = Utattemita人格
favicon / metadata / footer / copyright = United Studio人格
```

具体的な実装：

- Header: `UTATTEMITA by UNITED STUDIO INC`
- Footer: `UTATTEMITA by UNITED STUDIO INC`
- favicon / app icon: USIブルーアイコン
- 右上UIやHEROグラフィック: UtattemitaのPOP人格
- copyright: United Studio Inc.へリンク

サイト固有の人格を強くしても、出所と責任主体は曖昧にしない。操作UIとブランド帰属UIは、同じ見た目へ統一しなくてもよい。

## 8. Core Candidates

以下は、今回の実装からUDSL Coreへ昇格できる可能性が見えた判断である。現時点では候補であり、正式仕様ではない。

- サイトごとに人格を変えてよいが、帰属と信頼は統一する。
- 入口サイトは、詳細説明をすべて抱え込まなくてよい。
- HEROは、対象者の心理を動かす役割へ集中できる。
- 信頼はHEROで完結させず、必要なタイミングで戻してよい。
- External Handoffは、移動先とそこでできることを明示する。
- サンプルは実績展示ではなく、体験理解として扱える。
- Mobileでは、見出し改行をレスポンシブの結果ではなく設計対象にする。
- 操作UIとブランド帰属UIを分けてよい。

これらはUtattemitaの視覚スタイルではなく、異なる人格と複数サイトを扱う際の構成判断としてCore化を検討する。

## 9. Utattemita Extension Rules

以下はCoreへ一般化せず、Utattemita固有に残すべきルールである。

- 写真をHEROの主役にしない。
- 教室感に戻さない。
- アイボリー中心にしない。
- 丸ゴシックによる安心感へ寄せすぎない。
- POP / FUN / 攻めを最初に出す。
- サンプルを大量掲載しない。
- ボイストレーニングを必須導線にしない。
- `rec`、`studio`、`reserve` へ役割分担する。
- CTAは、最初から「予約する」と迫らず、「歌ってみたい」「空き状況・料金を見る」を使う。

シアン、ピンク、ステッカー、グリッド、ポスター感はUtattemitaの実装語彙である。これらを、そのままUDSL Coreの共通スタイルへ昇格させない。

## 10. Implications for united-studio.com

次に制作する `united-studio.com` 本体は、各専門サイトを均一な会社サイトへ戻すのではなく、複数の創作入口を束ねるハブとして設計する。

- `studio`、`yosakoi`、`utattemita`、`reserve`、`rec` を統合的に見せる。
- 各サイトの人格を均一化しすぎない。
- United Studio本体を「共通の会社感」ではなく「複数の創作入口を束ねる場」として扱う。
- 本体ではCore人格を示し、各Extensionへの入口で表情を変える。
- 各サービスを単なるメニューではなく、創作の始まり方の違いとして見せる。

Utattemitaで確認できたのは、親ブランドの一貫性と、入口ごとの異なる人格は両立できるということである。本体サイトは、その違いを消すのではなく、関係として見せる必要がある。
